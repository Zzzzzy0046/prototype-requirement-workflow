# 如何检查必要提问

这是虚构教学正例，不是真实业务确认。查看 request.md 后沿需求 id → expressions → scene key 追踪。

未回答时：把 Q001 状态设为 open，并去掉 answer/answerSourceId；校验应拒绝完整预览与写入。不要选择一个推荐答案代替用户。

回答后：当前文件已放入明确标记的虚构答复，完整规划应通过。生成结果只包含 Home，不因为按钮进入文件选择就新增页面。

与确认无关的排版：沿用 profile 的尺寸与字号，不问用户每一个间距。若换成其他模板，先更新计划选择和场景，不复用 Printer 业务规则。

回归中的反例还包括原文被改、下游页面越界、无来源控件、部分交付掩盖遗漏、假答复、遗漏需求和错误映射。通过结构校验仍需语义与实际渲染检查。
