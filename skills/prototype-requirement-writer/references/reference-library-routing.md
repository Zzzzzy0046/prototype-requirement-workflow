# 同类参考库选择与页面密度

本规则用于用户只给少量页面需求、要求“参考以前的原型”，或当前页面容易被画成空骨架时。参考库用于提升信息架构、页面密度和表达一致性，不代替当前产品需求。包内 [RP 原稿派生的通用页面模式库](rp-pattern-library.md) 是所有使用者都可直接使用的默认参考，不依赖原始 RP 或本机路径。

## 1. 先识别，再找参考

先从当前输入和有效基线识别四项：产品族、平台、页面类型、主任务。先在包内 `rp-pattern-library.md` 选择页面模式；如果用户本轮提供了 RP/图片/HTML，或项目明确配置了 `reference-library/`、`.axure-workflow.json` 的 `referenceRoots`，再从授权范围寻找更具体的参考。用户允许且当前已连接时，可用 Mobbin 补真实行业案例。不得为了找参考扫描整个电脑，也不得把另一个历史项目自动接管为基线。

参考顺序：

1. 当前产品、当前平台、用户指定版本的有效基线；
2. 用户本轮明确提供的同产品族、同平台、同页面类型完整 RP；
3. 包内 RP 派生模式库中对应的页面模式，作为无外部材料时的通用主参考；
4. 用户授权范围内同产品族、同页面类型但平台不同的材料，只参考信息结构；
5. 不同产品但同页面类型的材料，只参考模块密度、布局层级和说明颗粒度；
6. Mobbin 中同品类、同平台、同页面/流程的真实产品案例，用于补行业信息架构和状态模式；
7. 仍找不到合适参考时，使用 `house-review` 骨架和产品常识生成提案，不声称已读取外部案例。

默认只选一个主参考或主模式，必要时最多增加两个辅参考/模式。主参考负责页面层级与密度；辅参考只能补状态表达或控件样式。模式库全量随包提供不等于每次全量套用；不要把多个产品或页面模式拼成“功能大杂烩”。

用户指定基线和包内 RP 派生模式比 Mobbin 更接近本技能的需求写法；Mobbin 不覆盖输出规范。无论外部参考使用圆角卡片、真实品牌色或高保真组件，最终仍按用户指定模板或 `house-review` 生成低保真画板、蓝色编号、右侧中文说明和独立 Axure 控件。

用户明确要求“直接复刻 RP”时，不走普通“结构参考”口径，改读 [实际 RP 页面直接复刻](direct-rp-replication.md)。此时要把候选 RP 的页面树和目标页原生渲染作为选型证据；同产品、同平台、同页面类型的可用页面存在时，功能脑图、流程图、模式库和 Mobbin 都不能替代它成为 UI 主参考。

## 2. 完整基线与局部迭代不能混用

先给候选材料标记版本角色：`full-baseline`、`current-baseline`、`partial-iteration`、`bugfix`、`research` 或 `placeholder`。

- 完整新品稿或明确的当前基线负责整体页面树、Home 密度和跨页关系。
- 局部订阅、广告、登录、启动、体验优化或 Bugfix 稿只负责其声明的改动范围，不能因为版本号更新就成为整款产品的页面模板。
- 明确的回退、替换、撤回关系优先于文件时间、文件名版本号、画布位置和文字颜色。
- 同一页混有新逻辑、旧逻辑、预研问题和占位时，按条目判断，不把整页统一标为有效。
- 包内模式库已经完成上述脱敏归纳；使用时不需要原始 RP。若本轮另有外部 RP，仍按 source-review.md 独立甄别。

## 3. Mobbin 的使用边界

Mobbin 可用于搜索同品类 App 的 Home、onboarding、list、detail、settings、paywall 等页面或 flow。检索时组合“产品品类 + 平台 + 页面/流程 + 关键状态”，先看 3–5 个候选，再选择与当前主任务最接近的一个作为结构参考；不能只因视觉漂亮就选中。

- 允许借用：信息层级、主次入口关系、模块角色、状态切换方式、导航模式和说明需要覆盖的交互节点。
- 不直接借用：品牌视觉、截图资产、受版权保护的具体文案、价格、权益、权限理由、广告策略、指标和后台结果。
- Mobbin 页面一律记为 `reference`，不能成为 confirmed requirement 的唯一来源。
- 只有实际通过已连接的 Mobbin MCP/API 或用户已登录页面读取到结果，才能写“已参考 Mobbin”；未登录、无权限或工具未连接时使用本地库/fallback，并如实记录。
- 不在 Skill 或提交包内保存账号、API key、Cookie 或下载的 Mobbin 截图；是否可访问以当前用户的账号权限和明确授权为准。

## 4. 参考选择记录

制作原型前，在项目 `reference-selection.md` 记录，并把逐页选择同步到 page-plan version 2 的 `referenceSelections`：

- 当前产品族、平台、页面类型和主任务；
- 候选参考或包内页面模式、实际读取范围及选择理由；
- 主参考与辅参考分别借用什么：信息架构、模块密度、状态表达、视觉样式或控件模式；
- 明确不继承什么：业务文案、价格、权限、广告、成功判定、数据口径和产品专属流程；
- 未找到合适参考时的 fallback 及本轮假设。

`direct-rp-replica` 还要记录：源 RP 标识、源页面名或 ID、原生读取/渲染是否成功、复刻的五个维度，以及因当前需求而发生的替换项。只写“参考某 RP”而没有页面级证据，视为未使用。

不是整款产品只选一次参考。完整产品按功能页分别选择：Home、权限/系统交接、列表、详情、编辑、结果和 Settings 可以使用不同主模式。若多个页面确实共享同一基线，也要逐页说明实际读取的页面范围与借用内容。

使用包内模式时记录模式名，不伪造源文件名。“文件存在”不等于“已参考”；对于本轮外部材料，至少读取相关页面树和目标页面，能够渲染时再检查画面。只有字符串表时，不据此判断页面布局与当前有效状态。

## 5. 一页范围不等于空页面

“只做 Home”限制的是页面树范围，不是 Home 的内容量。除非用户明确要求空骨架、单一概念验证或忠实复刻极简原稿，否则不能用“避免猜测”为由只画标题、一个状态和一个 CTA。

Home 在提交前至少检查以下角色是否已被当前需求、有效基线或低风险提案覆盖：

- 用户打开页面后能识别当前产品状态或当前内容；
- 主任务有清晰、可执行的首要入口；
- 与主任务直接相关的高频辅助入口或内容区已判断是否需要；
- 用户完成过任务后，页面是否需要承接最近内容、结果、历史或继续操作；
- 导航、设置入口或页面去向是否足以让页面成为真实产品主页；
- 空态、未授权、未连接、无记录等状态只有在会显著改变页面结构时才补静态画板。

这些是覆盖检查，不是固定模块清单。页面可以没有 Recent、底部导航或设置，但必须有当前产品理由。若最终只剩标题和一个 CTA，应在 `reference-selection.md` 写明为什么极简结构成立；否则视为页面表达不足。

## 6. 参考内容如何进入需求模型

- 用户或有效基线明确的内容：按原来源记为 `confirmed`。
- 参考库启发、且不改变权益/费用/权限/删除/成功判定/数据归属的页面模块：可作为 `assumption` 进入 requirements-model，并在 scene.assumptions 和交付说明中披露。
- 会改变产品方向或用户后果的参考规则：不能直接画成定稿，按 clarification.md 提 1–3 个关键问题。
- 纯视觉层级、间距、模块密度和控件模式：记录为参考范围，不反填成业务 requirement。

同类参考可以回答“一个成熟 Home 通常需要哪些信息角色”，不能回答“这个产品一定有哪些业务规则”。如果参考与用户当前要求冲突，以用户当前要求为准。

参考的需求说明颗粒度按 reference-driven-quality.md 继承。不能只借用画板宽度和蓝色编号，却把原稿中的页面进入、展示规则、交互分支、系统返回和异常边界压缩成摘要。

## 7. 快速反例

错误：用户说“做一个扫描仪 Home”，Agent 因为没有完整 PRD，只画 App 名和 `Scan` 按钮。

正确：先选同类工具 Home 作为结构参考，围绕扫描主入口、当前设备/权限状态、最近扫描或继续任务、辅助导入入口形成提案；低风险新增标 assumption。若“必须连接设备后才能选文件”会改变主入口可用性，再只问这一类关键问题。

错误：参考 Printer Home 后，把连接打印机、Print Document、打印历史复制到 Document Reader。

正确：只借用主任务优先级、状态区和最近内容区的层级；模块名称、按钮结果和数据规则重新从 Document Reader 的当前来源生成。
