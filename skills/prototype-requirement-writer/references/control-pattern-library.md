# 可编辑低保真控件模式库

本模式库把用户原 RP 中反复出现的控件表达抽象为跨产品组合规则。它不要求导入特定 `.rplib`；当前桥接即使只使用 Rectangle、Paragraph、Ellipse，也应组合出足以评审的语义控件。所有子控件保持可单独选中，不创建 Group、Layer 或整页根 Frame。

scene version 2 的业务控件使用 `componentRole` 标记角色。标记用于证明页面采用了什么控件模式，不改变 Axure 的基础形状类型。

## 1. 基础页面骨架

| 模式 | 组成 | 适用页面 |
| --- | --- | --- |
| Status Bar | 时间、网络/电量占位、背景 | 移动端页面需要系统上下文时 |
| App Bar | 返回/菜单图标、标题、右侧操作 | 二级页、详情、编辑页 |
| Bottom Navigation | 图标占位、标签、选中态 | 有明确一级页面结构时 |
| Tabs | 标签、选中颜色/下划线、未选中态 | 内容分类或模式切换 |
| Section | 标题、内容容器、分隔或留白 | Settings、Home、Detail |

不能只画手机框、标题和一个大按钮就视为完整页面。screen 类型默认至少包含四种语义角色，并至少有一种页面专属复合控件。

## 2. 内容与任务模式

| `componentRole` | 最低表达组成 | 常见用途 |
| --- | --- | --- |
| `illustration` / `image` | 资源边框、图形占位、必要说明 | 引导、空态、弹窗插图 |
| `thumbnail` | 缩略图、类型/状态标记、对象信息 | 文件、照片、页面预览 |
| `list-item` | 图标/缩略图、主副文案、状态、更多入口 | 文件、设备、历史、设置项 |
| `card` | 对象/状态、核心信息、相关操作 | Home 状态、结果、订阅权益 |
| `input` | 标签、输入值、提示/错误、清除或单位 | 文件名、搜索、数值设置 |
| `camera-view` | 取景区、识别提示、拍摄区域和控制层 | 扫描、拍摄 |
| `crop-handle` | 边界线、四角点、预览对象、旋转/重拍/确认 | 裁边编辑 |
| `chart` | 坐标/区间、趋势线或柱、图例/缺失状态 | 趋势与分析 |

图片占位不能只是写“IMAGE”的空灰框。至少表达资源比例、内容焦点或状态用途；需要美术出图时在画框外增加 art note。

## 3. 操作与选择模式

| `componentRole` | 必须可辨认的状态 |
| --- | --- |
| `button` | 主次级、可用/不可用；文案与说明一致 |
| `toggle` | On/Off 与当前值；说明保存时机 |
| `radio` | 单选项、选中项和提交方式 |
| `checkbox` | 多选、半选或不可用状态（实际存在时） |
| `menu` | 触发对象、菜单项和危险操作层级 |
| `tab` | 当前选中与可切换项 |
| `drag-handle` | 可拖动对象和拖动范围 |

不要用普通 Paragraph 假装所有图标和操作。无图标资源时可以用简化符号，但应作为独立 `icon` 控件并保持可编辑。

## 4. 弹层、系统交接与反馈

| `componentRole` | 组合要求 |
| --- | --- |
| `overlay` | 保留触发页面上下文并加半透明遮罩 |
| `dialog` | 标题、说明、主次操作；危险操作有明确确认层级 |
| `bottom-sheet` | 圆角/顶边、标题、内容、主操作、关闭方式 |
| `system-surface` | 与 App 自有页面区分，并在框外说明系统负责范围 |
| `feedback` | Toast/Snackbar/错误条，说明出现条件、消失和后续操作 |
| `progress` | 当前任务、真实进度或不定进度、取消/离开规则 |
| `banner` | 运营或状态信息、入口和关闭规则 |
| `ad-slot` | 广告类型、占位范围和“仅示意”标注；有当前业务来源时才出现 |

弹窗不能只画一个孤立白框。需要同时显示其所在页面、遮罩和弹层层级，才能评审触发上下文。系统页面不能伪装成 App 页面。

## 5. 页面类型的最低组合检查

这些是控件覆盖检查，不是固定功能清单：

- Onboarding：Status Bar + illustration/image + content + primary button；有跳过时补次入口。
- Permission/System handoff：触发页上下文 + 说明/插图 + action；涉及系统弹窗时补 overlay + system-surface。
- Home：App Bar/品牌区 + 主任务入口 + 当前状态/内容区 + 必要辅助入口或导航。
- List/History：搜索/筛选（实际存在时）+ list-item + 状态/更多操作 + 空态差异。
- Detail/Edit：App Bar + 主内容/预览 + 操作 + 保存/返回状态。
- Settings：App Bar/标题 + Section + list-item + toggle/radio/跳转值；不要把整页设置项压成一个矩形。
- Result/Progress：progress/feedback + 结果对象 + 后续操作；处理中、失败、成功结构明显不同时分画板。

页面可以因当前来源更简单，但要在 `reference-selection.md` 说明为什么删去某类模式；不能因为桥接只支持基础形状就降低需求表达。

## 6. 真实性与打包边界

- 实际导入 `.rplib` Master 才能称“复用组件库”；基础形状组合统一称“参考控件模式重建”。
- 不把原 RP 图片、文案、价格、权限理由、广告频次或产品数据打进包。
- `componentRole` 是语义标签，不代表 Axure 原生 Widget 类型，也不承诺动态交互。
- 页面丰富度来自与当前任务匹配的控件组合，不来自无意义地堆图标、卡片或装饰。
