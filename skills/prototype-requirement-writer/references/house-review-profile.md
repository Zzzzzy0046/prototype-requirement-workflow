# RP 原稿归纳的通用评审格式

本格式只定义新原型的评审视觉骨架，不定义业务说明目录，也不继承任何一个样例产品的功能。它来自对用户提供的 32 个 RP 的只读盘点：共识别 267 个页面记录，其中 201 个页面完成结构化解析，覆盖约 3.7 万个控件；29 个文件为 RP9，3 个为 RP11。未完整解析的页面不作为细节定稿依据，原 RP、原文和扫描报告不进入提交包。

## 1. 统一骨架

- 新 scene 默认 `noteProfile: "house-review"`，page-plan 使用 `template.profile: "house-review"`。旧项目保留原 profile，不为换样式重建页面或映射。
- 页面树按 Home、Reader、Settings 等功能组织；状态是同页静态画板，不把 Home 拆成多个 Axure 页面。
- 标准移动端画板宽 360px。常规画板高 640px；内容确实为长页时允许向下延长，不把长页压缩回 640，也不裁切原文。
- 手机框使用白底、`#797979`、1px 直角描边。低保真 App UI 优先使用 Arial；真实控件库或指定平台模板有字体依据时保留其字体。
- 每组评审单元遵循“框外画板标题 → 页面效果 → 紧邻说明”。单页、多状态、流程、局部迭代、Bugfix 和共享规则都沿用该骨架。

## 2. 几何与文字

以下数字按原稿重复结构归纳；坐标可整体平移，内部相对关系保持：

| 元素 | 规范 |
| --- | --- |
| 画板标题 | 位于手机框上方 36px；Arial 13.5pt、700、`#333333`，高度至少 21px |
| 同组多个画板 | 1–2 个横排；3–4 个默认按 2×2 向下排列；更多状态继续按每行最多两个画板向下分组。相邻画板间距约 32px；下一行标题与前一框底部默认留 24–36px，只有独立流程组或额外说明时才扩大间距 |
| App 内控件 | 当前产品指定 RP/组件库优先。没有当前模板时，才参考原稿常见的白底、直角、`#D0D0D0` 轻灰 1px 线框和清晰主次按钮作为低保真 fallback；不固定某个示例产品的按钮尺寸、颜色、卡片结构或平台控件 |
| 说明编号 | 编号表示同一功能页内的需求模块，不表示画板、状态或布局行；每个独立标题与正文必须一对一配置编号。标题顺序来自当前页面的业务说明目录，不按某个示例产品的固定章节递增。外圈 26×26、内圆 22×22，主色 `#3758CC` |
| 说明文本起点 | 每个编号与对应说明标题同高，标题位于编号左边缘向右 38px；同一模块可同时覆盖多个状态画板 |
| 说明模块纵向间距 | 按实际正文高度连续排列；下一编号通常位于上一模块正文底部后 8–12px，不使用固定的大步长，不为了与画板行对齐而留下大段空白 |
| Axure 对象结构 | 默认不创建 Group、Layer 包裹或整页根 Frame；页面框、标题、正文、编号、按钮等均为可单独选中和编辑的叶子控件。批量写入只代表一次原生 Undo，不代表控件成组 |
| 说明标题 | Arial 10.5pt、700、`#333333`，行高约 21px |
| 说明正文 | Arial 9pt、400、`#333333`，默认列宽 322px，单行间距约 20px |
| 美术交付标题 | 只在确有资源交付时出现，Arial 13.5pt、700、红色；置于 App 框外，不默认写数量 |

scene 坐标不必复刻原文件的绝对 X/Y；编译器还会整体增加 40px。生成时按上表计算相对位置，不能把实验版大字号说明、570px 宽说明列或 438px 手机框继续当作默认。

视觉骨架不能反向决定业务内容。profile 可以固定画板、编号和说明的相对位置，但不能要求每页都有“页面进入/交互说明/异常处理”，不能从 Printer、Reader、Heart Rate 或 Find Phone 示例复制状态、按钮和结果。页面内容密度由 reference-library-routing.md 基于当前任务和同类参考判断；`house-review` 既不强制堆满模块，也不允许把单页请求自动降成空骨架。

## 3. 模板类型

### 单页面

一个主画板配右侧说明。说明目录可混合页面生命周期标题与业务对象标题：简单权限/弹窗页可直接使用“页面说明、页面进入、交互说明、边界&异常处理”；多模块页面再增加对象级标题。页面用途已经由其他模块讲清时可以不单独写“页面说明”，但不能因此省略进入、返回或异常规则。

### 同页多状态

同一功能页内排列多个 360px 画板，框外标题用 S01、S02、S03 标明状态。1–2 个画板横排；3–4 个默认 2×2；更多状态继续向下分组，每行最多两个画板。右侧 1、2、3 是页面需求模块序号，独立于画板行数和状态序号；共同规则只写一次，状态差异在对应模块正文中逐项指明适用的 S 编号，不因状态多而新建多个 Home。

### 启动或任务流程

流程顺序、条件和回退写在说明；只画对视觉评审有意义的节点。不得把箭头或页面缩略图当作完整页面需求，也不从其他产品复制广告、订阅或权限顺序。

### 局部迭代与 Bugfix

仅放受影响页面。需要视觉比较时画旧/新两个静态画板，并用 change 说明写旧→新、影响范围、沿用部分与回归点；不重绘全部产品。

### 共享规则与表格

跨页面规则只保留一个 requirement id，在实际受影响页分别映射。重复字段用 table，方向、条件和例外不能压成“全局同步”。表格可以增宽；普通说明仍用 322px 列。

## 4. 组件复用与真实性

- 原稿中最常见的是 `需求常用库 1 / Box 1`、`安卓5.0 / Heading 2`、Default Heading/Paragraph、Primary Button、Image、Ellipse、Marker、Table/TableCell，以及含子对象的 Layer。
- 库名和 style MatchInfo 只能证明来源元数据存在，不能证明当前工作流已经导入对应 Master。没有捕获原模板时，统一表述为“参考原稿，以可编辑基础控件重建”。
- 基础框、标题、说明、编号和表格可以由当前通道生成。复杂 Layer、真实图片、矢量路径或库 Master 未被直接导入时，不声称无损复用。
- 新 scene 即使仍由基础形状组成，也按 control-pattern-library.md 组合并标记 componentRole；图片、列表、选择、弹层、系统界面和反馈不能全部退化成无语义的大矩形。
- 业务文案、订阅价格、广告频率、SDK、权限流程、健康阈值、人员和内部链接永不进入通用模板。

## 5. 交付检查

1. 核对功能页身份与画板状态，没有机械拆页。
2. 核对 360px 框、标题、编号、说明起点、字体和宽度；长文扩展说明高度，不缩字号。
3. 每个业务控件和说明都有 requirement 映射；装饰控件登记 decorations。
4. 美术、研发和运营备注在 App 框外且语义分开。
5. HTML、Markdown 和 Axure 使用同一 scene 文案；Axure 写入后回读并检查原生整页渲染。
6. 仅在实际复用 Master/模板时写“复用”；基础控件重建须如实说明。
