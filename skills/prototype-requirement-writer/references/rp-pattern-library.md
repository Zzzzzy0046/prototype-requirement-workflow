# RP 原稿派生的通用页面模式库

本文件把已走查的一批多产品 RP 抽象成 Skill 内置页面模式。它不是原文件目录，也不保存原文、截图、业务数值、账号、路径或可反推出具体项目的信息。使用这些结构检查和表达规则不需要持有原始 RP。

抽象覆盖 32 份 RP、267 个页面记录，其中 201 页完成结构化解析；其余页只用于文件与页面覆盖统计，不作为控件或布局细节依据。模式库回答“这类页面通常要检查哪些信息角色、状态和说明”，不能回答“当前产品一定要实现什么”。当前需求、用户答复和有效基线始终优先。

## 1. 使用方法

先判断任务形态，再选择一个页面模式作为主模式；必要时最多选两个辅模式补状态或说明类型。不要把所有模式拼到一个页面。

1. 确认任务是完整新品、单页、流程、局部迭代、Bugfix 还是共享规则。
2. 从下表选择与主任务最接近的页面模式，而不是按示例产品名称选择。
3. 将模式中的“信息角色”逐项判断为：当前来源已确认、低风险提案、不适用、需要提问。
4. 只把已确认内容和明确披露的低风险提案画入页面；高后果规则先问。
5. 最终使用 `house-review` 的画板、编号和中文说明，不复刻来源项目视觉。

## 2. 页面模式

### A. Home / 主任务入口

适用于工具、内容、设备、测量、搜索等产品主页。

- 核心信息角色：当前对象或状态、首要任务入口、与主任务直接相关的辅助入口、任务完成后的承接区、必要导航。
- 常见承接区：最近内容、继续任务、最近结果、设备状态、趋势摘要；只选与产品闭环有关的项。
- 候选状态：首次使用、已有内容、未授权、未连接、无记录、任务进行中。只有布局明显变化时才画成独立静态画板。
- 说明重点：入口条件、主按钮结果、对象来源、完成后返回或新增什么、状态如何恢复。
- 禁止机械继承：底部导航、Recent、订阅入口、设备卡片、广告位或某个固定 CTA。

### B. 启动 / Onboarding / 首次里程碑

- 核心信息角色：启动节点、首次与非首次分支、语言/引导/权限等节点、完成里程碑、跳过与返回落点。
- 必须分清：冷启动、热启动、回前台、系统返回；“看过某页”和“完成首次流程”不是天然同义。
- 画面只保留需要视觉评审的节点，完整顺序和条件写在说明或流程表。
- 广告、订阅和权限顺序属于高后果规则；没有当前来源时不得由历史模式补入。

### C. 搜索 / 扫描 / 选择来源 / 发起任务

- 核心信息角色：输入或目标对象、来源选择、主动作、处理中反馈、取消/重试、结果入口。
- 多来源进入同一任务时，先写共同处理逻辑，再列相机、文件、设备、历史等来源差异。
- 输入合法性、权限、设备条件、免费次数、成功判定和失败是否留记录需要明确来源。
- 画板可表现空闲、输入完成、处理中、失败；仅文案变化时用说明，不复制整屏。

### D. List / History / Recent / Collection

- 核心信息角色：记录单位、排序/分组、空态、单项动作、批量动作、继续任务或详情入口。
- 说明重点：记录何时生成、显示哪些字段、状态标记、删除范围、排序是否持久化、失败项如何重试。
- 删除记录、删除原对象、移除收藏和清空缓存必须分开；不默认级联。
- 当同一条规则影响 Home、History 和 Detail 时，使用一个共享 requirement，并列适用页面与例外。

### E. Detail / Result / Preview / Edit

- 核心信息角色：对象身份、主内容、可执行动作、编辑状态、保存/完成、返回、错误恢复。
- 区分默认值、临时值、预览值和已保存值；Apply、Done、返回、Discard 各自是否提交必须一致。
- 说明结果由什么事件产生，失败或取消是否生成历史、消耗次数或改变上游列表。
- 编辑后只更新真实依赖页面；不要泛写“全局同步”。

### F. Device / Permission / System handoff

- 核心信息角色：当前可用性、连接或授权入口、扫描/等待状态、系统页面、成功返回、拒绝/断开后的恢复。
- App 自己的状态和系统真实状态分开；模拟扫描、示意连接或系统页截图不得写成真实能力已完成。
- 平台、系统版本、权限后果、后台能力和外部 App 返回属于需验证信息。
- 系统页面仅供参考时在框外标注，无需伪造成 App 自有页面。

### G. Measurement / Trend / Insight

- 核心信息角色：测量入口、实时反馈、结果、保存、历史、趋势、解释或提醒。
- 说明必须统一采样单位、成功条件、自动/手动保存、删除后重算、时间区间、缺失值与零值。
- 日均、记录平均、自然周期、滚动周期、最近一次和最高/最低值不能混用。
- 健康阈值、诊断式文案和系统传感器能力不得从样例迁移，需当前证据与合规检查。

### H. Settings / Preference / Account

- 核心信息角色：设置项当前值、入口、选择控件、保存方式、系统跳转、订阅/账号状态、恢复默认。
- 明确即时生效还是提交后生效，返回或关闭是否放弃未保存修改。
- App 功能开关、单次任务开关、暂停和系统权限不是同一个状态。
- 设置项只纳入当前产品确有的能力，不因模式库存在而补齐整页菜单。

### I. Subscription / Entitlement

- 核心信息角色：权益、方案、价格来源、试用/低价期、续费说明、关闭、购买结果、Restore、已订阅状态。
- 订阅页只是页面模式；是否出现、何时出现、方案和权益都必须来自当前需求。
- 视觉可以低保真重建，但价格、折扣、默认方案、倒计时、免费次数和关闭策略不得从历史稿继承。
- 购买成功、取消、失败、待处理和恢复购买后的返回路径要与权益生效事件一致。

### J. Ads / Push / Shared policy table

- 适合用表格或共享规则块，不必为每条规则画一整屏。
- 广告至少区分广告类型、位置、触发事件、资格、频次/间隔、失败兜底和订阅豁免；推送至少区分触发、受众、时间、内容池、点击落点、取消与生命周期。
- 共享计时、计数或去重只保留一个规则源，各页面引用，不能复制后各自演化。
- 广告 ID、SDK 版本、频率、推送文案池和商业策略全部需要当前来源。

### K. Global flow / Cross-page rule

- 用于启动链路、外部邀请恢复、跨页同步、共享状态机、统一异常处理。
- 先写共同规则，再写入口差异、适用页面和例外；区分“受影响页面”和“本轮要绘制页面”。
- 流程图表达顺序与条件，不能代替每个功能页的视觉和行为说明。
- 外部跳转后保留对象 ID、来源页和临时数据；是否恢复到原任务必须有当前规则。

### L. Iteration / Bugfix / Version delta

- 局部迭代只放受影响页面，使用旧→新、影响范围、沿用内容和回归点；不重画完整产品。
- Bugfix 写复现入口、实际行为、期望行为、影响分支和回归点，不顺便改视觉或商业策略。
- 文件名版本号不是自动继承链。明确回退、替换、撤回优先于时间和编号；全量新品/当前基线负责整体结构，局部迭代稿只负责其声明的改动范围。
- 同页混有正式改动、旧逻辑、预研问题和占位时，按条目判定效力，不整页标 confirmed。

## 3. 说明块模式

按内容选用，不要求每页齐全：

| 类型 | 适用内容 | 关键要求 |
| --- | --- | --- |
| `module` | 单页业务模块或操作 | 一个蓝色编号对应一个标题和正文 |
| `shared-rule` | 多页共用规则、全局状态 | 写适用页面、触发、例外；不复制多份正文 |
| `change` | 旧→新、迭代或 Bugfix | 写影响范围、沿用与回归点 |
| `table` | 广告、通知、字段、方案矩阵 | 保留行列语义，不拍平成散乱段落 |
| `art` | 插图、图标、状态稿等美术交付 | 与业务说明分开，写表达目的和复用范围 |
| `question` | 影响当前结果的未决项 | 区分业务、技术、美术；只问必要问题 |

## 4. 内容密度与组合

- 单页先形成“识别当前状态/对象 → 执行主任务 → 承接结果”的最小闭环，再决定是否需要辅助入口或导航。
- 复杂度来自业务关系，不来自堆控件。一个成熟 Home 可以只有三个高价值模块，也可以有更多；每个模块都应能说明其用户任务。
- 1–2 个状态画板横排；3–4 个按 2×2 向下排列；更多状态继续向下。编号表示需求模块，不表示画板数量。
- 一个主页面模式负责结构；辅模式只补一个明确缺口。例如 Home 可辅以 Device 状态，但不能把 Device、Subscription、Ads、Trend 全部默认拼进 Home。
- 用户只要求一个页面时，下游页面用“进入对应流程，本轮不展开”收口，不因模式库而扩大页面树。

## 5. 必要提问边界

以下内容一旦影响当前页面或用户后果，优先给简短推荐并提问，不以模式库代答：

- 主用户与首要任务不清；
- 多个入口谁是主入口会改变页面结构；
- 权限、设备、支付、广告或登录是否阻塞主任务；
- 成功事件、保存时机、删除范围、计数扣减或跨页同步不清；
- 平台能力、健康/金融结论或合规敏感文案缺证据；
- 多版本之间存在回退、替换或冲突且无法从来源确定。

普通布局、标准控件、低风险信息层级和不改变业务后果的辅助展示无需询问；可作为 assumption 呈现，并允许后续局部修改。

## 6. 禁止迁移

无论模式来自多少份 RP，以下内容都不能变成通用默认值：产品名、真实 UI 文案、订阅价格与权益、试用策略、广告频次与 ID、通知内容池、权限理由、SDK/接口、健康阈值、成功回调、内部链接、人员、排期、指标、截图资产，以及来源文件中的跨产品残留或待预研结论。

交付时只说明“使用内置 RP 派生模式库”，不能声称已打开或复用了当前任务未提供的原始 RP；只有实际导入 Master/组件时才写“复用控件”。
