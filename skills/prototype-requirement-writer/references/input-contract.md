# 输入归一化与内部提示词

用户可以只说“做一个 Printer 的主页，有连接打印机、照片和文档入口，右侧写中文说明，放进 Axure”。也可以提供 PRD、HTML、图片或现有模板。这些都是有效输入，不强制用户使用模板。

Agent 先按 page-expression.md 整理 requirements-model.json 和 page-plan.json，按 clarification.md 解决必要问题。下列信息的简要结论再进入 scene.brief（字符串）及 scene.assumptions / outOfScope（数组）；完整来源和问题不能只压缩成一段 brief。

| 内容 | 处理方式 |
| --- | --- |
| 产品、页面/流程范围 | 用户本轮明确要求优先；不扩大成整款 App |
| 使用人群、任务 | 只写依据明确的信息；缺失的低风险假设标明 |
| 平台、UI 语言、说明语言 | 用户要求优先，否则移动端低保真、海外英文 UI、中文说明 |
| 参考资料、定稿文案 | 逐份查看；区分参考布局与要求逐字保留的原稿 |
| 交付形态与基线 | 新品/局部页面/迭代/Bugfix；明确产品、平台、有效版本及继承范围 |
| 证据状态 | 已确认、历史参考、待预研、占位、未读取或冲突；不能统一当成正式要求 |
| 页面、模块、按钮结果 | 分配稳定 key，串联具体行为 |
| 状态与边界 | 挑实际相关项；不机械列全状态 |
| 目标 RP、输出目录 | 来自项目配置或用户提供的绝对路径；不得猜测 |
| 不做内容、待确认项 | 明确记录；不将假设写成事实 |

将上面内容代入以下稳定任务指令。这是 skill 内部操作，不需要用户复制：

> 根据本次交付形态、用户已确认需求和实际读取材料，为指定产品/平台/版本制作可评审低保真页面与中文说明。先区分有效基线、迭代差异、参考、预研和占位，不能混用历史规则。保留定稿文案和必要英文 UI 标签；每个功能页面保持身份，必要状态用同页静态画板表达，每组图紧邻对应说明并保持编号。围绕模块写出入口/条件、动作、结果、保存时机、取消/失败与返回，跨页面的数据与计数保持一致。只采用来源明确的业务值，关键冲突单列，低风险假设明确标识。迭代写明旧→新、影响范围和沿用部分。将布局与文案放进同一份 scene.json，统一生成 HTML、说明和 Axure 控件。按授权范围完成可视检查与 Axure 回读，再报告真实结果。继续修改沿用 key、映射和目标 RP，不重建项目，不添加未要求的商业化模块或复杂交互。

将以上稳定指令用于三段内部处理：先提取有来源的事实和缺口；再按必要提问规则收口并规划每条需求的表达去处；最后套用选定模板生成 scene。不得省略中间决策，直接从自然语言猜坐标。

已有原稿说明时，notes.lines 使用原文行，并在模型 exactCopies 记录对应目标，不经过第二轮“润色”。新增说明以页面说明开头，其余按真实模块和必要的状态/交互/异常组织，不强制六段标题。新写说明使用 `1、2、3、`，不强制重编已有定稿编号；同一段文字在 HTML、Markdown 和 Axure 都由此字段直接输出。基线与来源细节放项目 source-review.md，简要结论进入 brief；不要向严格 scene schema 添加自造字段。

“通用”指可用于同事自己的不同产品需求；Printer 只作为演示输入，不能成为默认业务模板。
