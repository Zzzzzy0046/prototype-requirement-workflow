# 待实现：模糊输入的主动收敛

状态：**仅讨论/建议，尚未实现，未指定下一版本号。** 当前发布为 1.5.0。本次归档不代表用户授权自动继续开发这些事项。

## 要解决的问题

现有 Skill 可以接受自然语言、按资料执行并提出必要问题，但对“用户只有一句模糊想法”如何引导，尚未做充分行为验证。不能将完整样例和结构校验通过，等同于同事随便描述也能稳定完成业务设计。

目标：用户无需知道技术流程，也不必一次提供完整需求；关键业务仍由用户决定。减少输入门槛，而不是减少有必要的判断。

## 建议的最小修改范围

1. 判断任务：方案探索 / 依据执行 / 定点修改 / 明确的演示样例。
2. 先利用当前项目、有效基线和已回答内容；不查无关历史会话，不重复问已有答案。
3. 信息不足时先提出一个简短推荐方案，说明范围与取舍，再让用户确认关键方向。
4. 区分可读取、低风险默认、必须决策三类信息；不把推荐、预选或沉默当作确认。
5. 足以支撑当前交付即可生成；下游仅被提及时不扩页，也不为单页索取完整商业方案。
6. 业务阻塞与写入环境阻塞分开；目标 RP 未提供时可先完成授权范围内的本地规划，再在写入前明确目标。

保留既有来源、partial、原文、映射与写入保护。不增加复杂 Axure 交互、更多构建适配、自动反向同步、比赛文档或强制收益问卷。

## 行为验收建议

| 输入 | 预期观察 |
| --- | --- |
| 只有一句“做一个主页” | 识别为需要方案收敛，提供简短推荐，不连发长问卷 |
| 一份完整 PRD +“按这个做” | 优先读取，直接执行明确内容，只问真实缺口 |
| 多个有回退/冲突的旧版本 | 找有效产品与基线，无法判定才提问 |
| “改这个按钮” | 保留原范围、key 和已确认上下文，不重做方案 |
| “你决定，做个示例” | 使用明确标注的合成假设，不伪造实际用户确认 |
| 关键问题用户没回复 | 不把建议当答案；仅明确的无关部分可继续 |

衡量：是否误判任务、重复提问、过度提问、无来源新增、把未知写成确认；是否能将回答反映到模型/表达/说明，而不是只改 questions.status。
