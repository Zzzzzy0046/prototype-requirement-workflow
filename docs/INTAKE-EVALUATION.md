# 主动收敛行为试跑

日期：2026-09-15。对象：1.6.0 Skill 指令，不是 Axure 适配器。使用三个不继承主对话历史的独立 Agent，各自读取同一 Skill 与必要参考；未提供标准答案或主 Agent 的预判。后续短回复在相应 Agent 内继续，以测试上下文延续。

评估方式：主 Agent 检查最终回复、实际需求/计划/scene、校验结果及修改前后差异。所有输入是合成测试，不冒充真实同事独立试用。产物保存在被 Git 忽略的 private/intake-eval 内，不随通用包分发。

## 输入

### A：只有一句话，再逐步补充

1. “帮我做一个 Printer 的主页。”没有资料或已确认基线。
2. 对 Agent 的入口范围问题只回复“继续”。
3. 明确接受文档/照片两入口；只展示已连接状态和指定英文文案；下游不画，不加历史、订阅、底部导航；只输出 HTML 和中文说明。

### B：完整需求，再做局部修改

1. Paper Shelf 只读文件库，Home 正常态显示标题和 Report.pdf；点击文件进入 Reader，Reader 不画，不展开内部规则；明确排除搜索、上传、删除、登录、订阅、底部导航；排版自主，只输出 HTML 和中文说明。
2. “把 Report.pdf 改成 Annual Report.pdf，同步页面和说明，其余不动。”

### C：明确授权的虚构示例

“你决定，先做个虚构的任务列表 Home 示例让我看看，只有任务列表和任务详情入口，HTML 和中文说明即可，不要连接真实账户。”

各 Agent 的工具边界相同：限定各自输出目录，禁止读取其他项目/任务或评估文档，不启动 Axure、浏览器或外部服务。禁止真实输入工具，必要问题在回复中提出。这些环境约束不作为用户业务确认。

## 本轮已观察

- A 首轮：给出顶部设备状态与打印入口的简短推荐，只问文档/照片是否都包含，没有索要 PRD、RP 路径、参数表或完整产品方案。
- A 第二轮：没有把“继续”自动解释为业务选择；保持原问题，没有生成候选内容冒充正式原型。
- B 首轮：不重复提问，生成单个 Home，保留 Paper Shelf / Report.pdf，未绘制 Reader 或新增排除项；规划通过。
- C：直接出单 Home 示例，4 条任务及详情入口；自主内容/顺序/入口细节记录为 assumption，与场景假设对应；规划通过，没有将其伪装为实际用户逐条确认。

后续生成与局部修改的最终核对汇总在根目录验证记录.md，不能仅以 Agent 自述代替结果核对。

最终补充核对：A 第三轮生成单 Home，Print Document / Print Photo / Printer connected 精确保留，下游及排除项未新增；原问题只以明确的第三轮答复标记 answered，未使用“继续”作为 answerSource。B 第二轮的 scene 与首版逐字段比较，恰好只将 Report.pdf 替换为 Annual Report.pdf；页面、控件、说明 key、坐标与其余内容均保持不变，页面和说明都同步更新。

三个 Agent 共六轮请求均完成上述观察，生成的三组原型规划校验均通过。没有额外的业务确认问卷、没有要求测试用户填写 JSON 或运行脚本。原始输出中的交付环境说明有少量进入 notes，本次未继续做说明文风调整；不能将此次通过理解为所有原稿风格均一致。
