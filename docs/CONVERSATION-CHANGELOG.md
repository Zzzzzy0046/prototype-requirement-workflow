## 2. Axure 写入路线与初期错误

用户明确拒绝将 Computer Use、键鼠操作或粘贴包装为 MCP 写入能力。早期文件实验曾出现无法打开、版本显示不符合预期及空引用错误。

最终路线与边界：

- 使用本地自建 MCP、对应版本桥接与 Axure 原生模型编辑，不依赖剪贴板传输或伪造文件版本头。
- 首次仍需目标版本保存的合法空白 RP，不宣称可以任意从零构造 RP 文件。
- 读取 RP9 或转换研究副本不等于支持 Axure 9 写入；文件格式与运行时版本兼容分别判断。
- 失败/超时先读状态，pending 表示结果未知，不能直接删除标记或盲重试。

没有把早期故障描述当作当前已全部覆盖的通用修复保证。

## 3. 静态页面与原稿表达方式

用户反复确认：不需要复杂交互和动态面板，用必要静态画板与文字说明即可；Home 就是 Home，不默认按状态拆成独立页面；要求全部范围时，不自行缩减为半版。

落实规则：

- 页面树按功能组织，状态优先放同页画板；不同导航目的地才建立独立功能页。
- 左侧页面效果、紧邻右侧中文说明，必要英文 UI 文案留在 App 内。
- 说明围绕真实模块、编号、行为和边界，不机械套满空标题。
- 用户提供定稿文字逐字保留，疑似问题单列，不暗中润色。
- 优先读取指定 RP/控件库；基础控件重建不能声称实际复用了原 `.rplib` 实例。
- 安卓评审样式作为可选 profile，不让所有同事继承某个演示产品业务。

## 4. 从反复生成文件到同一 RP 持续修改

用户要求：不希望每次得到一个新 RP，也不希望靠关闭重开才能看到修改。

已实现机制：

- 稳定 page/widget/note key 与原生 ID 映射。
- 同进程、同一 RP 中连续更新；内容不变时零新增/修改。
- 指纹检测外部编辑、手动撤销或异常并发；冲突时停止而非覆盖。
- 写入后回读文字/几何、保存和原生渲染。

限制：不是全自动双向实时同步；人工在 Axure 修改后的回流仍需读取、核对和协调。跨页写入不是事务，不自动撤销前面成功的批次。当前 runner 不支持删除/改类型/重命名已映射对象的任意迁移。
