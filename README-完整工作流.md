# 需求到 Axure · 完整交付包 1.9.2

唯一 Skill 入口是 **prototype-requirement-writer**。它把产品功能框架、用户手动上传的竞品截图、PRD、参考图或已有 RP 转换为可评审的低保真页面、中文需求说明，以及可选的 Axure RP 11 原生页面。

## 标准信息流

```text
产品功能框架 + 手动上传的竞品截图 + 本次范围与禁止事项
  → 读取输入和有效基线
  → 功能树、页面清单、状态清单、竞品低保真抽象
  → 必要提问
  → 用户确认页面清单
  → page-design：只生成页面
  → 用户确认页面画面
  → final：补齐逐页中文需求说明
  → 可选：写入并持续修改同一个 Axure RP
  → 回读、原生渲染和保存
```

产品功能框架决定功能范围、页面清单和页面分布；竞品截图只用于抽象布局、信息层级、模块密度、控件组合和状态表达，不能提供当前产品的价格、权限、广告、保存、删除或成功判定等业务规则。

默认使用 `house-review` 评审格式：左侧页面效果，右侧紧邻对应的中文需求说明；海外 App 界面默认英文。多状态使用静态画板和文字描述，不默认制作复杂交互或动态面板。

## 给 Agent 的首次任务

解压后，让 Agent 先完整读取：

- `skills/prototype-requirement-writer/SKILL.md`
- `skills/prototype-requirement-writer/references/` 中由 SKILL 路由的相关规则
- `examples/README.md`，仅在需要理解数据结构或页面表达时读取

推荐调用：

> 使用 `$prototype-requirement-writer`。这是一个 Android 新品。附件 1 是产品功能框架，附件 2～N 是竞品截图。本次范围是【范围】，禁止【禁止事项】。功能框架决定页面和状态分布，竞品截图抽象为低保真结构。请先输出完整页面清单，不要开始画。

用户不需要填写 JSON，也不需要自己编写专业 Prompt。Agent 只询问会改变页面清单、关键业务规则或高后果行为的必要问题。

## 两道确认门

### 1. 页面清单确认

第一次只交付页面规划，至少包括页面名称、目标、入口与出口、关键状态、功能框架来源、竞品结构参考和未决问题。页面漏项在这里修正，未得到用户真实确认不能进入完整制作。

### 2. 页面画面确认

页面清单确认后，先使用 `page-design` 生成完整页面控件，不生成右侧需求说明。用户检查页面是否齐全、信息量、控件组合、状态表达和整体紧凑度。确认后进入 `final`，再生成逐页说明。

需求说明按页面内模块编号，不把蓝色 1/2/3 误当作页面编号。说明必须覆盖出现条件、页面进入与退出、控件行为、状态变化、数据规则、结果反馈，以及空态、失败、取消、返回等边界；不能只复述界面文案。

## Axure 写入

需要 Windows、PowerShell 7、Node.js 20+、可执行本地脚本的 Agent，以及 Axure RP 11。当前提供以下精确版本适配器：

- 11.0.0.4134
- 11.0.0.4137
- 11.0.0.4149

其他 Axure 11 构建拒绝写入，不承诺跨版本兼容。首次使用仍需在目标 Axure 版本中新建并保存一个空白 RP，然后关闭该文件；后续由 Agent 自动启动桥接并持续修改同一个 RP。

日常不要求用户手动运行脚本。Agent 读取 Skill 后调用根目录 `ensure-axure.ps1`，完成依赖检查、版本识别、连接复用和恢复。需要独立初始化或排错时可使用：

```powershell
.\开始完整工作流.ps1 -Workspace 'C:\PrototypeProjects\MyProject' -ProjectRp 'C:\PrototypeProjects\MyProject\Prototype.rp'
```

只生成 HTML 预览时：

```powershell
.\开始完整工作流.ps1 -Workspace 'C:\PrototypeProjects\MyProject' -PreviewOnly
```

工作流不使用 Computer Use、键鼠模拟或剪贴板粘贴。新建页面和控件使用自建 MCP Bridge 写入 Axure 文档。

## Reference 使用边界

`examples/reference/` 和 `references/rp-pattern-library.md` 用于稳定页面结构、控件密度、说明组织和低保真风格，不是固定产品模板。优先级始终是：

```text
当前明确需求
→ 当前项目有效 RP 基线
→ 用户提供的竞品截图抽象
→ 内置页面模式库
→ 脱敏 reference 示例
```

示例不能替用户决定权限、订阅、广告、保存、删除、成功判定、数据归属或平台能力。用户明确要求复刻已有 RP 时，必须逐页读取并渲染真实源页面，不能用概览页、框架图或通用卡片重新发挥。

## 使用边界

- 不自动抓取竞品截图，目前由用户手动上传；
- 不自动优化产品功能和业务流程，除非用户明确要求；
- 不因为只做 Home 就把页面降成标题加单一按钮；
- 不把一个页面的状态机械拆成多个页面树节点；
- 不将页面和说明 Group 起来，保持控件独立可编辑；
- 不承诺任意 HTML/CSS、复杂图标或 `.rplib` 无损转换；
- 不把 HTML 预览当作 Axure 已写入成功的证据；
- 写入失败或状态未知时先回读，不盲目重试。

使用后产生的 `sessions/`、`session.json`、`axure-map.json`、`history/`、`output/`、原始需求、RP 和截图留在项目本机，不得写回提交包。
